# 设计记录 · 2026-11-07

一次集中改造的记录：**改了什么、为什么、还欠什么**。
比 CHANGELOG 更啰嗦，因为这里记的是判断过程，不是结果。

---

## 起点：三个不满

1. **AI 被放错位置**：它原本是一个独立菜单项。但 AI 应该是一种「能力」——
   关掉它，应用必须依然完整；打开它，记录才越用越聪明。
2. **主题是整屏染色**：选绿色就整个界面变绿，很难看。颜色应该是
   「明暗」×「强调」两个独立维度。
3. **记录太累**：手工记录要求每天做一次作业，这才是六年间放弃四次的真正原因。

## 中间的关键判断

### 判断一：这是档案馆，不是记录器

用户的原话是「换软件时丢的不只是数据，还有过去的自己」。
这句话决定了产品的第一原则不是「记得准」，而是**「随时能离开，数据不丢」**。

落到代码：原始层不可改写、投影层可重算、导出必须全量。

### 判断二：15 分钟是原子单位

自动录制一天 300 条，1 分钟粒度全是碎片。15 分钟是「一件事」的最小可信单位：
15 分钟里切了十次窗口，但 9 分钟在 Word 上，这一格就是写材料。

代价：**精确到分钟的时长在展示层看不到了**。这是有意的取舍——
展示层要回答「在做什么」，不是「切了几次窗口」。精确数据仍在记录层。

### 判断三：分类要少，少到能一眼选中

从 13 类收敛到 7 类（工作/学习/生活/娱乐/睡眠/专注/其他）。

理由不是「好看」，是**记录成本**：每多一个分类选项，人就要多判断一次，
久了就不记了。细分类留给机器推断，人只做最终确认。

### 判断四：单击不创建任何东西

最初的实现是「点空白 = 新建 15 分钟」，结果用户误触就多一条，还删不掉
（因为删除用错了日期，找不到标注）。

改成系统日历的模型：
- 单击空白 → 什么都不发生
- 按住拖动 → 划出区间 → 松手打开编辑器 → **保存才落库**

原则：**写操作必须有明确的「确认」动作**，不能靠撤销来兜底。

### 判断五：记录层不可拖，但可编辑

拖动一块自动录制的色块，等于篡改「那段时间电脑确实在做什么」。
所以：可编辑（生成一条标注覆盖它），不可拖动、不可删除。
要学会区分「事实」和「解释」——这是整个分层的地基。

## 这一轮暴露的真 bug（值得记住的教训）

| 现象 | 根因 |
| --- | --- |
| 日历点了没反应 | 插入弹窗时用「第一个 `</template>`」定位，把时间轴卡片的闭合截断了，弹窗被塞进 `v-for` 里，日历视图下根本不存在 |
| 浮层透明 | `teleport` 到 body，脱离了 `.app-root`，主题 CSS 变量全部失效 |
| 删不掉新建的块 | 删除用「当前选中日期」，而日历显示 3~7 天，点的是别的日期 |
| 优先级没生效 | `normalizeRaw` 把导入来源压成了 `auto`，四层优先级变成两层 |
| 窗口「很窄」 | DevTools 停靠占了一半宽度，误判成布局问题 |
| 改了没效果 | 旧 Electron 实例没重启，看的是旧代码 |

共同点：**都是「我以为在改 A，实际在改 B」**。
教训是：能用 DOM/数据验证的，不要靠截图猜。

## 现在还没做好的

1. **周报生成器**：唯一一个「每周都会用、用完有产出」的功能，优先级最高。
2. **项目维度**：只有应用和分类，但人想知道的是「商户迁移这个项目花了多少时间」。
3. **计划 vs 实际**：滴答清单知道计划，LifeLog 知道实际，两个一对就是最有价值的偏差。
4. **历史回填**：2026-02~03 的旧数据没有时长，那 34 天在热力图上是空的。
5. **导出**：「随时能离开」这条承诺还没有兑现成按钮。

## 明确不想做的

- 社交、排行榜（这是觉察工具，不是打卡）
- 强制云端（本地优先是承诺）
- 图片视频存储（先只存引用）
