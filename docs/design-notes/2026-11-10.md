# 设计记录 · 2026-11-10

## 这一轮解决什么

应用和分类只能说明“用了什么工具”，不能稳定回答“在推进什么事情”。本轮在会话之上增加活动线程：利用相邻关系、窗口标题、展示分组和短暂辅助切换，把连续会话归并成一个可核对的活动。它是本地投影，不写回记录层，也不宣称已经理解用户意图。

## 已实现

- `buildActivityThreads` 输出活动名称、起止、时长、主要分类、涉及应用、切换次数、置信度和是否待确认。
- 首页显示“今天推进了什么”；低可信线程提供核对入口，高可信线程可显式确认并写入可撤销标注层。
- 区间报告汇总跨日活动线程，供趋势和周回顾使用。
- 首页提供确定性周回顾草稿，可复制 Markdown，并与前一周比较；低可信活动不进入主要活动列表。
- 分类设置分为七个大类和高级细类例外；细类默认继承大类的积极/平稳/消耗设置。
- 高可信活动确认时可以改名并添加项目；时间线编辑也能补充或清空项目。
- 项目可通过应用名/窗口标题关键词自动识别，规则只参与可重算投影，不改变原始采样。
- 周回顾优先展示跨日期项目投入；没有项目时回退到主要活动。
- AI 分类建议只接收低置信度活动线程，高可信结果留在本地处理。

## 边界

- 活动线程仍是启发式投影，绝不自动写成人工标注；只有用户点击“确认”才生成覆盖标注。
- 未设置项目标签或识别规则时，同一项目在不同日期使用不同窗口标题仍可能被拆成多个线程。
- 周回顾是统计草稿，不推断产出、情绪或未记录时段。

## 计划到事实

计划、屏幕活动和事实不再是三个孤立模块，而是同一时间块的三个状态：

1. 本地计划或滴答《记录》只表达意图，不进入工时；
2. “按计划记入”显式生成一条人工事实；
3. “从屏幕活动生成”只确认已有采样的语义，不重复写入和累计时长；
4. 实际与计划不一致时，继续使用手工补记或活动线程确认。

本地计划保存在 `Data/plans/local.json`；计划确认状态与活动 JSONL 分开保存，删除计划不会误删事实。第一版只做单日本地计划，重复计划仍由滴答提供。

日历采用“计划池 + 时间轨道”并排结构：左侧计划可以拖到任意日期与刻度；本地计划移动时保留身份，滴答计划落入日历时生成本地副本。空白拖拽通过显式开关决定新增计划还是补事实，避免把意图误写成已经完成。右键复制使用独立的计划剪贴板，不与事实片段的复制粘贴混用。
