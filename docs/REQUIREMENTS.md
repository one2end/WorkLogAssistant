# LifeLog 需求总纲

> 这份文档回答三个问题：**它到底要解决什么、哪些规则不可动摇、还差哪些没做。**
> ROADMAP 讲「为什么这么判断」，ARCHITECTURE 讲「代码怎么组织」，这里讲「要什么、不要什么、先要哪个」。
>
> 最后更新：2026-11-08　版本：v1.0（需求基线，待确认 6 项开放决策）

---

## 一、定位

**一句话**：把「电脑上发生的每一分钟」不可逆地记下来，把「离线的时间」用最低成本补上，最后回答一个问题——**我的生活时间到底花在哪了。**

三个身份，按重要性排序：

| 身份 | 含义 | 对应的硬要求 |
| --- | --- | --- |
| **时间账本** | 部分取代日记：不靠回忆，靠事实 | 记录层不可改、全天可解释（不能有大片空白） |
| **档案馆** | 换了多少软件，「过去的自己」都还在 | 本地优先、开放格式、随时能全部带走 |
| **参谋** | 不只给数据，给结论 | 日报/周报可交付、能发现偏离、能回答「这个项目花了多少时间」 |

**它不是**：任务管理器（那个用滴答清单）、打卡社交产品、云端 SaaS、情绪日记。

## 二、需求的事实基础（决定了所有取舍）

六年记录史本身就是需求文档：

| 事实 | 数字 | 推出的需求 |
| --- | --- | --- |
| 手工记录会退化成批量补记 | 11% 条目同分钟批量勾选，单次最多 45 条 | 记录必须自动化，人工只做「确认/填空」 |
| 记录靠回忆不靠当下 | 延迟中位数 2.6h，12% 超 24h | 不允许把「记得准」当卖点，只保证「不会丢」 |
| 语义极稀薄 | 81% 只有标题无正文 | AI 的第一价值是补语义，不是写文章 |
| 换软件就断档 | UpTimer 745 条 → 断 → 滴答 2100 条 → 断续 → 本应用 | 导入器 + 单文件格式 + 全量导出是核心需求，不是附加功能 |

当前数据资产：**1085 个有效日期（2017-04 ~ 2026-11）、约 8800 个 15 分钟块**，来源 recorded / dida / uptimer / manual 四种。

## 三、不可协商的产品原则（P0 级约束）

1. **记录层是事实，不可修改、不可删除、不可逆。**
   错只能靠「上面盖一层解释」修正，不能改原始采样。→ 任何编辑/删除能力都必须被主进程拒绝，不能只靠前端隐藏按钮。
2. **展示层分层且有优先级。** 同一段时间只能有一个说法，高优先级覆盖低优先级，**绝不求和**。
3. **15 分钟是全系统原子单位。** 一天 96 格；写入时起点向下对齐、时长取 15 的整数倍、最小 15 分钟；专注数据同样服从。
4. **AI 是能力不是页面。** 关掉 AI，记录、统计、时间轴、日历、导出必须完整可用；AI 只做四件事：归类、汇总、发现偏离、出报告。
5. **任何需要「每天坚持」的动作都视为设计失败。** 新功能先问：不做会怎样？能不能自动？能不能一键确认？
6. **展示分类要少。** 展示层固定 7 组（工作/学习/生活/娱乐/睡眠/专注/其他），细分只留给机器与统计。
7. **数据只在本机。** 云端只允许「用户自己的同步盘目录」（iCloud/OneDrive），不做强制账号、不做订阅锁数据。

## 四、概念模型

### 4.1 数据分层

```
原始事实            解释            结论              出口
┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────────┐
│ 记录层    │ → │ 标注层    │ → │ 投影层    │ → │ 今日/日历/周报 │
│ 窗口采样  │   │ 人/AI 解释 │   │ 15 分钟格 │   │ Obsidian/MCP  │
│ 只追加    │   │ 可改可删  │   │ 可重算    │   │ 导出/检索     │
└──────────┘   └──────────┘   └──────────┘   └──────────────┘
   不可逆          有优先级        无状态          可丢失
```

| 层 | 存放 | 可变性 |
| --- | --- | --- |
| 记录层 | `activities/*.jsonl` 中 `source` 为空或 `recorded` 的行 | 只读 |
| 标注层 | 同文件 `source = manual / dida / uptimer`，以及未来的 `ai` | 可改、可删、可整层重算 |
| 专注层 | `arhat/sessions/*.json`、`dida/focus/*.json`（只读镜像） | 删镜像即可重拉 |
| 投影层 | `slots / sessions / categories / 日历块` | 每次实时重算，不落盘 |

### 4.2 优先级（同一段时间听谁的）

**用户口径（需求）**：

```
1  手工补记（离线事实：睡觉/吃饭/开会/外出）   ← 最高
2  专注（我主动声明这段时间在做什么）
3  AI 生成（AI 读记录层后推断「在做什么」）
4  记录层汇总（自动录制的 15 分钟归并）         ← 兜底
```

**代码现状**：`SOURCE_PRIORITY = { manual:4, imported:3, focus:2, auto:1 }` —— **缺 AI 层，且 imported 被压到 manual 之下**。

→ 需求与实现的差异见「八、开放决策 D1」。

### 4.3 一天的三种读法

| 视角 | 回答的问题 | 现状 |
| --- | --- | --- |
| 时间轴（卡片流） | 我今天依次干了什么、哪些是空的 | 已实现 |
| 自适应日历（1/3/7 列） | 时间块怎么排、有没有重叠/空洞 | 已实现 |
| 记录层（只读列表） | 事实到底是什么（可审计） | 已实现 |
| 统计（构成/应用/热力） | 时间去哪了 | 已实现 |
| 报告（日/周） | 这周值得说的是什么 | 单日 AI 摘要已有，周报未做 |

## 六、三条最重要的需求（如果只能做三件）

1. **AI 候选标注（D1）** —— 一切洞察的地基。现在「做了什么」的标签太稀薄，没有语义层，周报只是把数字换个说法。
2. **周报生成器（D2/E5）** —— 唯一一个「每周必用、用完有明确产出」的功能，也是这个产品对外的价值证明。
3. **口径统一（B2 + D1 的优先级）** —— 先把「同一段时间听谁的」定死，否则后面所有统计都不可信。

## 七、非功能需求

| 类别 | 要求 |
| --- | --- |
| 本地优先 | 断网可用；除 AI 调用与滴答同步外不出网；AI 可整体关闭 |
| 隐私 | 窗口标题可能含客户信息（银行场景）→ 排除名单 + 脱敏 + 敏感内容不落盘；导出时可选脱敏 |
| 可离开 | 数据是明文 JSON/JSONL/Markdown；格式有文档；三年后能用自己的代码解析 |
| 不可逆性 | 记录层只追加；任何「删除」只能是标注层或投影层 |
| 性能 | 冷启动 <2s；1086 天全量索引 <10s；时间轴/日历切换 <200ms |
| 健壮性 | 单文件损坏不影响其它日期；写入原子（tmp + rename）；崩溃不丢已采样 |
| 可维护 | 纯逻辑（归并/优先级/解析）必须有单测；主进程与 UI 严格分层 |
| 平台 | Windows 优先（Electron），不承诺移动端 |

## 八、开放决策（需要拍板，影响数据口径）

| 编号 | 问题 | 选项 | 建议 |
| --- | --- | --- | --- |
| **D1** | 优先级怎么定？ | A. `manual(5) > imported(4) > focus(3) > ai(2) > auto(1)`<br>B. `manual+imported 同级(4) > focus(3) > ai(2) > auto(1)`<br>C. 保持现状（无 ai 层） | **B**：滴答/UpTimer 的历史记录本质就是「当年的人工补记」，不该比今天的手工标注低；AI 必须单独一层且低于专注 |
| **D2** | AI 标注存在哪？ | A. 写进 `activities/*.jsonl`（`source='ai'`）<br>B. 独立 `ai/annotations/*.json` 镜像 | **B**：可整层删除重算、可换模型重跑，符合「投影可重算」；analytics 侧映射成 `source='ai'` |
| **D3** | 本地番茄钟还要不要？ | A. 保留，作为没装滴答时的兜底（默认关）<br>B. 彻底删掉，专注只从滴答来 | **A**：已实现且成本为零，但默认值应改为关闭，避免和滴答专注各记一份 |
| **D4** | 滴答推送要不要真开？ | A. 长期关闭只留代码<br>B. 只在「滴答当天没有对应条目」时才推 | **B**：否则必然和已有清单重复，这也是当初要求「先别双向」的原因 |
| **D5** | 记录层要不要允许「作废」？ | A. 绝对不可改<br>B. 允许追加一条 `excluded` 标记（原始记录仍在） | **B**：隐私与误录是真实需求，「不可逆」应指「不可抹除事实」，而非「不能声明这条不算」 |
| **D6** | AI 报告与 Obsidian `### 回顾` 是不是同一份？ | A. 两套独立产出<br>B. 同一次生成，双向落盘 | **B**：否则用户要在两个地方看两份不一样的周报 |

## 十一、术语

| 术语 | 含义 |
| --- | --- |
| 记录层 / 事实层 | 自动采样得到的原始窗口记录，只追加 |
| 标注层 / 展示层 | 人、导入或 AI 给出的「这段时间在做什么」 |
| 空档 | 没有事实也没有标注的时间段 |
| 格 / slot | 15 分钟，一天 96 格 |
| 纯度 / purity | 一个格内主导分类所占比例，低于 0.6 视为不确定 |
| 覆盖 | 有内容的时间占全天比例 |
| 专注 | 用户主动声明的计时区间（番茄钟或滴答专注） |
| 生活事务 | 生活 + 娱乐 + 睡眠，可显示但不计入工时 |
